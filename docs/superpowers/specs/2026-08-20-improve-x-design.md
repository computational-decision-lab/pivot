# IMPROVE-X Platform Design

**Status:** approved from the user-provided Goal V5 on 2026-08-20

## Purpose

IMPROVE-X is the reusable research platform behind the PIVOT paper. Its
scientific unit is an improvement transition generated by an operator,
`pi_t -> pi_{t+1}`, and its primary question is whether proxy improvement
survives observer, actor, and strategic deployment worlds.

The existing `pivot` package remains the compatible implementation of the
original PIVOT contracts. IMPROVE-X adds a stable platform facade and dataset
contracts without duplicating world or metric logic.

## Architecture

```text
ImprovementOperator
        |
        v
CandidateBatch -> PolicyTransition records -> World evaluators
        |                                      |
        v                                      v
ImprovementTrajectory                  observer / actor / strategic deltas
        |                                      |
        +------------------> ImprovementBench + FailureTaxonomy
```

### Operator contract

`ImprovementOperator.propose(incumbent, round_id, seed, **kwargs)` returns a
`CandidateBatch`. Existing `SyntheticPerturbation` and `RLUpdateOperator` are
adapted through a small protocol; no LLM dependency is introduced.

### Trajectory contract

`ImprovementTrajectory` stores every candidate transition, the selected
candidate, per-round world values, query cost, and promotion reason. It exposes
`cumulative_true_improvement`, `proxy_curve`, and `true_curve`. Failed and
unselected candidates remain in the record.

### ImprovementBench contract

The benchmark is JSONL plus a SHA-256 manifest. Each row contains policy
identities and serialized parameters, operator, proxy/deployment values and
deltas, response/footprint metadata, failure type, seed, round, and world
level. Tasks are sign prediction, candidate ranking, and failure explanation.

### Failure taxonomy

The platform uses explicit labels: `none`, `observer_failure`,
`environment_response_failure`, `strategic_failure`, `optimization_drift`,
and `unknown`. Classification is deterministic and only labels evidence
available in a row/trajectory; absent actor or strategic values remain null.

## Data flow and integrity

1. Generate candidates with a seeded operator.
2. Evaluate incumbent/candidate in matched contexts at each available world.
3. Construct a benchmark row and classify only observed failures.
4. Append rows without deleting failures or ties.
5. Finalize a manifest containing row count, schema version, source commit,
   and hashes for JSONL and metadata.

The benchmark package contains no credentials, live orders, private data, or
raw vendor archives. Existing public finance evidence remains observational.

## Validation strategy

- Unit tests cover immutable IDs, operator adaptation, trajectory promotion,
  null-preserving serialization, taxonomy precedence, benchmark round trips,
  sign/ranking/explanation tasks, and manifest tamper detection.
- An integration command generates a deterministic controlled benchmark and a
  multi-round trajectory from the existing performative world.
- Existing PIVOT tests, paper gates, and claim boundaries remain unchanged.
- New benchmark outputs are not promoted to the paper until a fresh run and
  scientific review establish the corresponding claim.

## Deliberate non-goals

No new trading strategy, MARL equilibrium solver, world-model reproduction,
LLM integration, authorization gate, or causal finance claim is introduced in
this phase. Those remain later adapters subject to explicit evidence gates.

# PIVOT 项目文档体系设计

**状态：** 已确认，面向团队交接实施
**日期：** 2026-09-15
**范围：** `/opt/projects/research/pivot`
**语言策略：** 中文主文档，现有英文科研文档继续作为权威原文

## 目标

让新加入项目的同事在不通读全部历史审计文件的情况下，能够回答四个问题：

1. PIVOT/IMPROVE-X 研究什么，当前结论到哪一步。
2. 理论对象、算法对象和实验对象如何对应。
3. 如何在本地复现、审计和继续执行实验。
4. 哪些结论可以写入论文，哪些门槛仍然开放。

## 文档架构

中文入口放在 `docs/zh/`，采用编号保证阅读顺序：

- `00_项目入口与当前状态.md`：项目简介、当前状态、证据等级、阻塞项和推荐起点。
- `01_研究问题与理论.md`：Improvement Fidelity、Improvement Reversal、理论命题、假设、证明边界。
- `02_算法与代码架构.md`：PIVOT、PIVOT-VOI、IMPROVE-X、数据结构、模块映射和算法流程。
- `03_实验设计与指标.md`：World 0/1/2、金融 F0-F2、V9/V15、对照方法、统计和终止状态。
- `04_运行手册.md`：环境检查、最小运行、主要命令、输出位置和常见失败处理。
- `05_结果与证据边界.md`：已完成证据、DEV/UNDERPOWERED/NOT_RUN 的含义和允许表述。
- `06_同事交接清单.md`：按优先级排列的接手任务，每项含输入、命令、输出和验收条件。
- `目录与文件地图.md`：源码、实验、配置、结果、论文和发布文件的职责索引。
- `文档维护规范.md`：权威源、状态更新、哈希和不夸大结论的维护规则。

根目录 `README.md` 只增加中文导航，不替换英文研究说明。现有根目录审计文件、`docs/` 英文说明、`paper/`、`results/`、`release/` 和配置路径保持不变。

## 内容原则

- 理论、算法、实验设计和证据状态分别说明，再通过文件地图互相链接。
- 所有状态以仓库中的 JSON、审计报告、注册协议和验证输出为准，不从文件名推断结论。
- `DEV`、`UNDERPOWERED`、`NOT_RUN` 和 `BLOCKED` 永远不改写成确认性结果。
- 命令使用当前 `.venv/bin/python` 和现有 `Makefile` 入口，避免产生第二套运行方式。
- 所有新增文档使用相对链接，便于 GitHub 浏览；涉及路径时写出仓库相对路径。

## 验证与交付

新增文档完成后执行：

1. Markdown 链接和引用路径检查。
2. `pytest -q` 与 `ruff check src scripts experiments tests`。
3. 论文/发布包现有验证入口，确认整理没有改动证据文件。
4. `git diff --check`、受控路径 `git status` 和提交内容审阅。
5. 将只属于 `research/pivot` 的更新提交到当前远程 `origin`，推送当前分支。

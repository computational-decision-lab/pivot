# 版本与审计索引

根目录保留 V9/V10/V15 文件，是为了维持既有脚本、发布包、相对路径和哈希证据。它们不是三个并列项目，而是同一研究的连续冻结层。

## 版本关系

| 层 | 角色 | 主要内容 | 当前使用方式 |
| --- | --- | --- | --- |
| V7 | 早期基线 | 初始 PIVOT 边界和旧发布快照 | 仅回溯；见 `snapshot/v9_preupgrade/` |
| V9 | 注册受控证据 | E2C、E3C、E4C、E5C、E7C | 当前可引用的历史受控结果；见 `results/v9/` |
| V10 | 论文/审计重建层 | 命题、指标、图表、参考文献和纸面审计 | 论文交付与审计历史；见根目录 `V10_*` |
| V15 | 当前工程与现代代理协议 | PIVOT-VOI、外部运行时、配对沙箱、密封任务平面、DEV 和发布包 | 当前工程状态和后续确认性执行入口；见根目录 `V15_*`、`results/v15/` |

## 当前权威优先级

1. 项目总状态：`docs/archive/v15/V15_FINAL_REPORT.md`、`docs/archive/v15/V15_IMPLEMENTATION_MATRIX.md`、`docs/archive/v15/V15_REPRODUCIBILITY_AUDIT.md`。
2. 发布包机器审核：`release/v15/submission_verification.json`、`release/v15/confirmatory_lock.json`。
3. 具体实验：对应 `results/<version>/<run>/scientific_decision.json`、`manifest.json` 和 canonical 表。
4. 理论和指标：`docs/research_question.md`、`docs/estimands.md`、`docs/claim_boundary.md`、`paper/main.tex`。
5. 历史台账：`docs/implementation-status.md`、`research/research_state.json`，只用于追溯。

## 文件如何阅读

- `V9_*`：V9 注册、失败、统计、复现和结果报告。
- `V10_*`：V10 论文交付、数字/图表/引用/声明审计。
- `V15_*`：当前实现矩阵、理论/足迹/闭环/战略分析、确认性锁、可复现性和最终报告。
- `docs/archive/v15/V15_FINAL_REPORT.md` 是当前状态入口；`docs/archive/v15/V15_FINALIZE.md` 是最终化流程记录。
- 所有 `DEV_ONLY`、`UNDERPOWERED`、`NOT_RUN` 状态必须结合原文阅读，不能升级为确认性结论。

## 为什么不移动

实验 runner、论文源文件、manifest 和 SHA-256 记录依赖现有路径。移动它们会让旧命令、快照和发布包失效，因此采用“原文件保留 + 版本索引导航”。

# 运行手册（Runbook）

> 从仓库根目录 `/opt/projects/research/pivot` 执行。所有运行使用项目 `.venv`；先做
> smoke，再做注册汇总，再做审计。确认性现代代理阶段必须在协议授权、运行时凭据和
> 人工确认完成后才可打开；默认命令不会触碰 sealed assessment。

## 1. 开始前检查

```bash
cd /opt/projects/research/pivot
.venv/bin/python --version
.venv/bin/pytest -q
.venv/bin/ruff check src scripts experiments tests
.venv/bin/mypy src scripts experiments
```

检查工作树、磁盘和 Python 依赖；不要在已有结果目录中重跑注册实验。确认
`configs/v15/confirmatory.yaml`、`configs/v15/external_versions.json`、
`experiments/v15/confirmatory_lock.json` 的 hash 与当前审计记录一致。外部运行时依赖锁在
`configs/v15/external_runtime_requirements.txt`，沙箱镜像 digest 写在 confirmatory config。

## 2. V9 受控实验

先运行单实验 smoke/dev，输出目录必须是新的：

```bash
.venv/bin/python -m experiments.v9.run --experiment e2c --profile smoke \
  --output results/v9/e2c-smoke --root .
.venv/bin/python -m experiments.v9.run --experiment e3c --profile dev \
  --output results/v9/e3c-development --root .
```

注册确认性运行按实验顺序执行（若目标目录已经存在，先选择新的外部输出根，不覆盖旧
证据）：

```bash
.venv/bin/python -m experiments.v9.run --experiment e2c --profile confirmatory \
  --output results/v9/e2c-confirmatory --root .
.venv/bin/python -m experiments.v9.run --experiment e3c --profile confirmatory \
  --output results/v9/e3c-confirmatory --root .
.venv/bin/python -m experiments.v9.run --experiment e4c --profile confirmatory \
  --output results/v9/e4c-confirmatory --root .
.venv/bin/python -m experiments.v9.run --experiment e5c --profile confirmatory \
  --output results/v9/e5c-confirmatory --root .
.venv/bin/python -m experiments.v9.run --experiment e7c --profile confirmatory \
  --output results/v9/e7c-confirmatory --root .
```

官方 Make 入口：

```bash
make v9-validate      # 严格检查 results/v9 manifest、schema 和确认性目录
make v9-analyze       # 生成 artifacts/v9/analysis.json、docs/archive/v9/V9_RESULTS_REPORT.md
make v9-figures
make v9-tables
make v9-audit
```

若使用注册 seed registry（P2/E4/E5/E6–E9），先 materialize 每个 registry，再独立聚合：

```bash
.venv/bin/python scripts/run_registered.py \
  --registry configs/registered/p2.yaml --output results/registered/p2
.venv/bin/python scripts/aggregate_registered.py --experiment p2 \
  --inputs results/registered/p2/p2-r01 results/registered/p2/p2-r02 results/registered/p2/p2-r03 \
  --output results/registered/p2-summary.json
```

将 `p2` 替换为 `e4`、`e5`、`e6`、`e7`、`e8`、`e9` 使用相应 registry；`f` 汇总需额外传
`--e8-inputs`，E5 可用 `--target-budget`，E6 可用 `--target-participation`。聚合器保留
failed runs，不把它们计入 gate。

## 3. 金融公开数据审计

公开金融数据是 observational execution audit。使用固定 manifest 获取数据，所有下载
文件按官方 SHA-256 校验：

```bash
.venv/bin/python scripts/fetch_public_finance.py \
  --manifest configs/data/binance_btcusdt_um_2023-01-01_07.yaml \
  --output-root data/public
.venv/bin/python experiments/e6_public_calibration.py \
  --config configs/finance/e6_public_calibration.yaml \
  --output results/raw/e6-public-calibration
.venv/bin/python experiments/e6_public_expansion.py \
  --config configs/finance/e6_public_expansion.yaml \
  --output results/raw/e6-public-expansion
```

扩展网格要求 3 个资产 × 4 个季度起点全部尝试；缺失或 checksum 失败必须写入 failure
ledger，并阻止“完整网格”表述。不得将百分比深度曲线写成已识别的 causal response。

不打开外部任务即可执行的本地检查：

```bash
.venv/bin/python -m experiments.v15 validate-pivot-core --root .
.venv/bin/python -m experiments.v15 validate-sandbox --root .
.venv/bin/python -m experiments.v15 dev-smoke --root .
.venv/bin/python -m experiments.v15 dev-construct --root .
.venv/bin/python -m experiments.v15 dev-resource-plan --root .
.venv/bin/python -m experiments.v15 validate-inspect --root .
.venv/bin/python -m experiments.v15 validate-mini-swe --root .
.venv/bin/python -m experiments.v15 validate-pi --root .
.venv/bin/python -m experiments.v15 freeze --root .
.venv/bin/python -m experiments.v15 freeze-candidates --root .
.venv/bin/python -m experiments.v15 run-promotion-replay --root .
.venv/bin/python -m experiments.v15 analyze-transitions --root .
.venv/bin/python -m experiments.v15 analyze-promotion --root .

.venv/bin/python -m experiments.v15 analyze-all --root .

```

`freeze` 是预结果锁定；已有锁会校验 hash，不会静默重建。`freeze-candidates` 只冻结候选
归档；promotion replay 使用同一 archive。开发 smoke 输出应落在
`results/v15/dev-*`，不具有确认性证据资格。

生成图表、论文和发布审计：

```bash
make v15-reports
make v15-figures
make v15-figure-review   # 需要人工完成 render/view/fix 后的 hash-bound sign-off
make v15-finalize
make v15-release
```

`v15-finalize` 会生成 numbers、claims、references、anonymity、language、reproducibility
和 terminal-state audits；失败或科学报告 `BLOCKED` 时，最终状态保持 `BLOCKED`。

## 5. V15 外部阶段（仅在锁定协议下）

默认命令返回 `NOT_RUN`，用于证明未意外打开外部阶段：

```bash
.venv/bin/python -m experiments.v15 run-transitions --root .
.venv/bin/python -m experiments.v15 run-promotion-replay --root .
.venv/bin/python -m experiments.v15 run-closed-loop --root .
.venv/bin/python -m experiments.v15 run-pi-replication --root .
.venv/bin/python -m experiments.v15 run-strategic --root .
.venv/bin/python -m experiments.v15 run-ablations --root .
```

授权后才可使用 `--external`；`--dev` 仅允许有限探针，不能宣称确认性：

```bash
.venv/bin/python -m experiments.v15 dev-external-smoke --root . --seed 10001 --task-limit 1
.venv/bin/python -m experiments.v15 run-transitions --root . --external --dev \
  --trajectories 1 --rounds 2 --candidates 2 --task-limit 1 --agent-steps 8
```

确认性命令必须去掉 `--dev` 和所有规模覆盖，并按依赖顺序执行：transition audit →
freeze candidate archive → promotion replay → closed-loop/assessment → Pi replication →
strategic response → registered ablations。每阶段都要检查 `manifest.json` 的
`phase=CONFIRMATORY`、`status=COMPLETED`、预期计数、lock hash 和输出目录不可覆盖。

## 6. 常见故障处理

- **目录非空/已存在**：不要删除旧结果；换新输出路径并在 provenance 中记录来源。
- **lock hash mismatch**：停止运行，比较 `confirmatory_lock_history.jsonl`、配置 hash 和
  当前文件；不能手改 lock hash。协议输入确需变化时，先走显式 refresh 流程并记录前序 hash。
- **seed 或 count 不符**：确认性 runner 会拒绝；不要通过减少 trajectories、rounds 或
  candidates 绕过门槛。
- **adapter unavailable**：保留 probe 输出为 `NOT_RUN`，安装/固定依赖后重新做 DEV probe；
  不把本地接口可用写成 scaffold 复现。
- **checksum/解析失败**：保留失败行和 manifest，修复数据源或配置后用新 run ID 重跑。
- **CI/审计失败**：先查看对应 `scientific_decision.json`、failure ledger 和 audit JSON；
  失败结果仍是证据，不能只保留成功 seed。

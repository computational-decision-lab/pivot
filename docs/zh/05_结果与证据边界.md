# 结果与证据边界（Results and Claim Boundary）

> 本文规定同事在报告、论文和 issue 中如何引用当前结果。状态以结果 JSON、manifest、
> 审计报告和发布验证为准；文件名或单次命令输出不能替代这些证据。

## 1. 状态词汇

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| `IMPLEMENTED_LOCAL` | 代码、schema、测试和本地 artifact 已实现 | 可做本地复现和接口审计；不能直接写科学优越性 |
| `COMPLETED` | 某阶段按其 manifest 完成并产出完整 artifact | 仍需核对是否 DEV 或 confirmatory |
| `Fixture Pass` | 注册受控 fixture 的预注册 gate 通过 | 只在该 fixture、seed、budget 和机制范围内引用 |
| `DEV_ONLY` | 有限开发运行，用于接口/构造诊断 | 不得作为确认性 effect 或泛化证据 |
| `UNDERPOWERED` | 有运行但独立单位不足，CI/终态不能支持判定 | 保留数据，扩大注册样本后重跑 |
| `NOT_RUN` | 执行入口明确未运行，`execution_attempted=false` | 不能描述为 null 或失败；按手册准备运行 |
| `BLOCKED` | 科学或人工门槛阻止最终结论/投稿 | 记录阻塞原因，不修改协议迎合结果 |
| `HYPOTHESIS_SUPPORTED` | 注册判定在声明的环境和准则下支持假设 | 不外推到未注册环境 |
| `HYPOTHESIS_NOT_SUPPORTED` | 注册判定未支持假设 | 作为结果保留，不改称实现失败 |

## 3. 金融公开数据边界

公开审计固定 BTCUSDT、ETHUSDT、BNBUSDT 的季度网格与百分比深度曲线，记录了可复核的
mechanical execution proxy。当前多资产汇总报告：primary depth mechanical effect 为
负，F1-positive sessions 上的 depth-proxy reversal 为 `0/7`（holdout `0/5`）。这些结果
说明该冻结 observational grid 未产生 reversal，并支持继续检查机制边界；它们不能识别
流动性补充、隐藏流动性、交易后响应或战略适应，也不能写成真实市场因果冲击。

每条公开审计 row 保留 `causal_impact_identified=false` 和 `live_orders=false`。更新
`position_size: 0.2 -> 0.6` 与 primary holdout 是探索阶段冻结的输入；在新的确认性
update-generation/holdout 规则正式注册前，不得称为确认性金融验证。

## 6. 允许与禁止的表述

| 场景 | 允许写法 | 禁止写法 |
| --- | --- | --- |
| 理论命题 | “在 `sup_pi |J_V-J_*|<=epsilon` 等假设下，得到 `|Delta_V-Delta_*|<=2epsilon`。” | “proxy 在现实环境中必然可靠。” |
| V9 E2C | “在注册受控环境与 operator 分布下观察到 shift 与误差相关。” | “所有环境中 update footprint 都导致 reversal。” |
| V9 E3C/E5C | “在固定候选池/HF budget 的 fixture 中，PIVOT-VOI 的 CISR 较低。” | “PIVOT-VOI 普遍优于所有方法/真实任务。” |
| V9 E4C | “当前 OOD comparison 未支持 differential ISC gain。” | “E4 失败是实现错误”或删除 null 结果。 |
| V9 E7C | “注册 opponent modes 下观察到 strategic effect。” | “证明了真实竞争市场的最佳响应规律。” |
| 公开金融 | “观察性 depth proxy 显示负 mechanical effect，未观察到 reversal。” | “证明了金融市场因果 reversal 不存在/存在。” |
| V15 DEV | “接口和审计链在有限 DEV smoke 中运行；结果 `UNDERPOWERED`。” | “现代代理确认了 IR/PIVOT 优势/跨 scaffold 泛化。” |
| V15 NOT_RUN | “confirmatory transition/promotion/Pi/strategic/ablation 尚未运行。” | “结果为 0”“没有 effect”“已验证。” |
| 投稿状态 | “机器检查通过，submission 为 `CONDITIONAL GO`，人工与科学门槛开放。” | “submission-ready”“全部 gate 已关闭。” |

任何新图表、摘要或 commit message 都应沿用上述状态词，不得删除 failure ledger、空
分母、独立单位或 CI。若结果与预期不符，保留结果并更新解释边界；不要回溯修改注册配置、
候选池、响应模型或 holdout 规则。

## 7. 继续工作的证据门槛

下一位同事应按以下顺序推进：

1. 核对 confirmatory lock、sealed manifest、sandbox image/dependency lock 与授权状态；
2. 完成并审计 mini-SWE transition audit，生成完整 canonical rows 和 terminal-state audit；
3. 在同一冻结 candidate archive 上运行 promotion、closed loop 与 assessment；
4. 不调参地完成 Pi replication、strategic response 和 registered ablations；
5. 重新运行 claims/numbers/reproducibility/language/reference/terminal audits，更新论文和
   supplement；
6. 关闭 external scientific gates 与投稿人工门槛后，才可把状态从 `BLOCKED` 改为可交付。

每一步都要提交 run ID、config/task/archive hash、seed/独立单位、失败 ledger、输出路径和
审计 JSON；没有这些元数据的数字只能作为本地调试记录。

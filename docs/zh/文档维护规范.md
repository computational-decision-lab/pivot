# 文档维护规范

## 权威文件

研究定义以 `docs/research_question.md`、`docs/estimands.md`、`docs/claim_boundary.md` 和注册协议为准；当前工程状态以 V15 final report、implementation matrix、reproducibility audit 和 release verification 为准；实验结论以对应 `scientific_decision.json`、manifest 和 canonical artifact 为准。

## 状态更新

状态只能由实际 runner 或审计器生成。`NOT_RUN`、`DEV_ONLY`、`UNDERPOWERED`、`BLOCKED` 和正式终止状态必须原样保留。补充样本不能覆盖旧目录，应创建新的运行目录并记录父版本、配置哈希和代码提交。

## 结果和论文

任何论文数字变化都必须同时更新源表、图表、claim audit、number audit、PDF 验证和 release SHA-256。不要手工只改 PDF 或只改汇总 Markdown。

## 安全和公开内容

密钥、私有路径、外部运行时日志、原始供应商数据和 sealed task 输入不得进入 GitHub。腾讯云 API、登录、库存或费用材料不属于 PIVOT 科研文档，本次整理不纳入发布包。

## 提交前检查

```bash
git diff --check
.venv/bin/pytest -q
.venv/bin/ruff check src scripts experiments tests
git status --short
git diff --stat
```

提交只包含本项目需要的文件；检查 `git diff --name-only`，确认没有父目录其他项目、密钥、缓存、临时目录或腾讯云 API 文档。

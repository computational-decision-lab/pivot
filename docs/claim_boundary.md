# Claim Boundary

## What PIVOT Studies

PIVOT validates whether a local learning update remains an improvement after deployment-induced mechanical and strategic response.

```text
We do not certify actions. We validate learning progress.
```

## Explicit Non-Novelty

Do not claim novelty from:

- iterative strategy generation, diagnosis, edit, verification, or promotion;
- evaluating policy-evolution trajectories in general;
- the existence of a verifier-deployment gap;
- policy-dependent environment dynamics or performative RL;
- policy-aware simulator training;
- multi-agent financial ecology or strategy competition.

EvoQuant/LLM systems are improvement operators. Learned market models are alternative interventional proxies. Competition is the strongest response layer, not a separate ecology contribution.

## Distinction From Existing Project Lines

| Project area | Core object |
| --- | --- |
| PEG | Prediction/evaluation ranking |
| EPV | Selected action |
| FinAuth | Authorization evidence |
| Intent-Cert | Execution route |
| LATTICE | External capability intervention |
| PIVOT | Fidelity of `pi -> pi'` under adaptive response |

PIVOT must never become an abstention, authorization, safety-permission, or route-certification method.

## Non-Goals

No factor-mining agent, HFT architecture, new trading RL algorithm, Sharpe maximization, market foundation-model training, M3 reproduction, general equilibrium solver, full multi-agent co-evolution, live trading, production trading infrastructure, KAIROS integration, or complexity for novelty optics.
